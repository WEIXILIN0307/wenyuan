## 实现边界

主导航通过 `#writer`、`#good-ai`、`#knowledge`、`#templates` 切换同一应用中的工作界面，
支持浏览器前进/后退和链接打开。切换界面时保留当前编辑器与保存队列，避免清空选区、
撤销记录或尚未发送的要求。刷新后从文稿列表重新打开已保存文稿。

Good AI 面向当前文稿，不承诺旧项目的通用知识问答、多轮自治、长期记忆或工具链。
模型仍仅输出原有受校验的建议；引用、base_revision、目标节点、原文校验和事务入口沿用
原实现。异步返回也检查当前队列，切换文稿后不会把旧输入/建议显示为新文稿的结果。

知识库继续使用 SQLite 与现有上传解析、chunks 和 FTS5。新增 `libraries`、
`library_sources`、`source_origins` 三张表，启动时增量创建，不重建文稿数据库。
文稿正文仍以原版本化 JSON 为唯一事实来源。

```mermaid
flowchart LR
  A[账号私有知识库] --> B[上传原件与版本片段]
  B --> C[SQLite FTS5 检索与原文核对]
  C -->|用户选用| D[文稿独立引用副本]
  D --> E[Good AI 输入与建议]
  E -->|预览确认| F[原有文稿事务与修订]
  F --> G[DOCX 导出与回读]
```

选用知识资料时复制其版本、原件和片段到文稿引用范围，记录原知识库名称。
同一资料重复添加到同一文稿返回已有副本。知识库删除或重新上传不会改变已选用依据；
删除文稿时仍清理其引用副本和索引。若需移除某份文稿依据，在文稿的资料面板单独删除。

所有知识库与原件端点检查账号所有权；引用复制同时检查目标文稿所有权。
上传沿用 10MB、文件名、类型、解压/XML、子进程时间与资源限制；不抓取外部 URL。
检索为字面匹配，不能当作事实核验或模型结论的真实性保证。

暂无自定义模板市场、任意 DOCX 模板分析、知识库共享、向量服务、自动摘要或自动学习。
这些入口没有做成不可用按钮，也没有拿旧项目的实现当成文渊已交付能力。
